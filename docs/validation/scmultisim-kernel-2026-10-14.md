# scMultiSim 派生内核实现记录（2026-10-14）

本记录区分软件实现、实际执行和正式科学校准。新增内核是独立 Python 实现的 scMultiSim 机制扩展；未调用官方 R 包。原版包与本扩展逐值等价、对真实生物系统有效、主学习器训练效果，均未在本轮验证。

## 已实现

- `scmultisim.py`：G/U/M 完整状态、共享网络参数、目标产生率持续缩放、双态启动子事件、分段解析 RNA、同步反馈、局部产生率敏感度、完整 JSON 检查点。
- `scmultisim_stationary.py`：两组初态与独立谱系的多窗口联合分布诊断、无反馈解析矩、公共 K 开发参考和 τ 减半比较。
- `scmultisim_observations.py`：独立条件／时间／重复／处理臂初态，稳定私有随机流，M 一次取整，参数／完整状态／J 真值与观测分离。
- `generate_scmultisim.py`：一张开发网络实际生成入口、原子文件、续跑校验、状态／失败记录、既有 BlindStore 门禁适配、正式盲测拒绝。
- 固定依赖和基础镜像摘要的 `linux/amd64` 数据生成镜像。

## 实际生成和数值诊断

Mac 使用最终源码和 `configs/scmultisim-small-development.json` 完整运行数据生成命令：

- 24 基因、16 调控者、40 边开发网络，网络种子 101。
- 共同基线与 36 个初始条件，共 37 个键，状态 `complete`。
- 每个处理／对照快照为 `(3, 4, 24)`；这是缩小细胞数的软件演练，不是正式 128 细胞实验。
- 公共 K 开发候选为 `5.081441499910911`，来自四个开发参考的无反馈解析平均 M。
- 初始分布在当前开发判据下以烧入 48 通过；全部快照非负，最终整数观测只包含 M。
- 同配置重新运行已验证跳过完成文件；文件校验和 BlindStore 重建通过，验证与最终预测仍未开放。

另以同一最终参数集实际生成一个完整细胞数条件（靶点 3，剂量 0.3，t=0.25）：处理与独立对照均为 `(3,128,24)`，处理最小／最大计数 0／19，Mac 本次调用耗时 9.178 秒。它验证单条件的默认细胞规模，不能替代整个 180 键批次的实测。

四基因独立机制演练（参数种子 101，诊断种子 501/502）：对照与靶点 0、剂量 0.7 的长期分布均在当前判据下以烧入 48 通过。实际生成长期处理及对照快照 `(3, 8, 4)`，最小观测为 0。这些是有限样本、有限时间下的开发诊断，不是唯一平稳分布的数学证明。

相同 128 条初态与启动子随机流、扰动 0/0.7、采样时间 0.25/1/4 下，比较 τ=1/32、1/64、1/128；两级分布比较均通过当前开发容差，启动子状态一致。t=4 的配对状态均方根误差分别为 `0.0005026175545484894` 与 `0.0002507662784668982`。这支持该夹具中减小反馈间隔降低数值差异，不替代四张开发网络的正式 τ 校准。

生成文件留在 Git 忽略的 `results/scmultisim-implementation-20261014/`，不提交细胞数据或私有真值。最终 x86_64 镜像实际完成 `tools/scmultisim/development_example.py` 的四基因真实生成实例：共同基线、靶点 0／剂量 0.7／t=1 扰动快照，以及独立长期分布，均为 `(3,4,4)`，计数范围分别为 0–13、0–12、0–10。对照与扰动长期诊断的烧入均为 48；指令模拟环境耗时 292.777 秒，退出码 0。原始摘要见[容器生成记录](scmultisim-kernel-2026-10-14-container.json)。先前主动停止的 24 基因容器长演练未计为完成。
